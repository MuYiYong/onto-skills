# 零售领域知识

## 定位与适用范围

将用户材料整理成可追溯、可组合的行业概念与关系交付物，支持本体和业务图设计。适用于术语对齐、范围澄清和模型裁剪；不执行业务操作、认证标准符合性或写生产数据。本包独立可用，不要求安装其他技能。

## 输入

最小输入：业务问题、SKU/地点/批次及单位范围、字段或脱敏样例、来源与评价时点。可选：GTIN/GLN映射证据、快照覆盖边界、原子运动/冲正记录、预留版本、在途明细、用户补货阈值及金额币种。

身份、时间、单位或政策缺失先列未决项，继续交付不依赖缺口的部分。

## 工作流程

1. 固定商品、地点、批次、状态、单位和时间粒度；同名商品、不同包装、未知批次不能自动合并。
2. 读[领域记录](references/domain.json)，将SKU/GTIN身份与库存状态、业务事件、商业单据分别列出。
3. 按[方法](references/method.md)声明快照覆盖边界，区分实存、预留、在途和订单/销售量；逐条保留来源与单位。
4. 明确原子库存事件身份、全部postings、冲正引用与晚到口径；退货接收和检验后可销售是不同事实。
5. 仅在用户给定规则时定义available与补货信号，单列不可判断的转换、金额币种或期间。
6. 输出概念关系、身份/时间/单位表、来源与未决项，按[示例](examples/worked-example.md)检查不重复计量与反证。

## 输出

- 范围、业务问题、评价时点及假设。
- 概念/角色表：name、business meaning、identity scope、lifecycle、source_ids、classification。
- 关系表：端点/方向、含义、基数条件、时间、来源和不确定项。
- 字段映射与损失；证据支持/反证；未决项、确认办法和质量结果。

## 质量检查

区分官方对象背景和项目建模建议；所有概念有来源与分类，不把模型选择称为官方定义。检查同名异义、身份范围、重复/晚到记录、时间与单位、正常反例。报告模型静态审查与实际运行的不同证据层级，不从缺失数据得出肯定业务结论。

## 标准依据与缺口

先核实包内来源与知识条目的standard_basis：固定发布机构、版次、具体定位和支持范围，再形成项目解释。standard_gap保留未核实映射、本地政策和补证路径；本地键、阈值或判定公式不因引用标准就成为官方定义。任务缺少适用版本或来源时交付不依赖缺口的部分，并明确待核实项。

交付时读取条目的standard_status：standard-backed仅表示standard_basis.scope内有已核实标准依据，其他本地规则仍按standard_gap保留；nonstandard-modeling明确标为“非标准建模”，标准未取得或精确映射未核实的原因一并列出。不得把背景页、目录或来源分类当成条目符合性。
