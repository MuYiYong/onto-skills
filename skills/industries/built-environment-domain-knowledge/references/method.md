# BIM交付与属性变更方法

1. 固定IFC 4.3.2.0和所需交换范围。保留原交付、散列、文件名/来源URI、交付修订、接收时间、完整性声明；单个STEP行号不是跨文件身份。读取GlobalId的实际值、类和模型谱系；变换或重导出造成新ID时要求显式映射，不用名称相似度自动连通。
2. 区分实例、类型、空间及属性断言。IfcRelContainedInSpatialStructure与IfcRelReferencedInSpatialStructure分别建边；同一交付的关系端点不能接到另一个修订。缺少空间信息不是“无影响”。
3. 只比较明确选择的属性集/属性名。先查实例，再查对应类型：存在但为空的实例值保留未知，不能以类型值补成事实。多个同名属性断言冲突时保留来源并停止该值比较。保留类型、名义值与单位，不把其他同名Pset的属性混入。
4. 按NominalValue的量纲解析显式单位或项目UnitsInContext。例子选的是**自定义**Project_Clearance.RequiredGap，类型IfcLengthMeasure，精确m/cm/mm换算，不是标准Pset或建筑安全距离。超出长度类型、复杂属性、数量、未知单位均需要新的映射。
5. 比较用户明确指定的before/after快照。同谱系、同GlobalId只在受控交付承诺下作为候选对应；内容冲突不取最后一条。局部交付缺项不推断拆除；完整交付缺项也只说明所选范围中未出现。
6. 所选可比属性确实改变后，列before/after主包含与引用空间的并集，保留每条关系及修订证据。这是空间复核候选，不是几何碰撞、停运范围、结构安全或施工批准。

## 输出字段与证据

交付：范围/修订对、标准与条目、对象身份表、类型/实例属性表、原始与规范化单位、变化/未变/未知、空间候选、定位和缺口。每个结论带source_record、source_locator、派生方式与政策版本。输入缺失仍可完成概念模型和缺口表，不伪造变化结果。

图模型的SourceRecord及其supersedes/derived_from是项目溯源；保留已知时点和完整原始交付。IfcRoot.OwnerHistory只提供有限最近修改信息，不是完整历史日志。属性图没有执行IFC EXPRESS、几何或全部逆属性约束，所有映射损失随交付传递。
