# electric-power-domain-knowledge

## 定位与适用范围

将电力业务描述或资产/状态数据整理成可溯源的领域词汇、身份边界和时序关系。适用于设备台账、拓扑/观测边界及停电候选范围讨论；潮流、保护整定、操作票、安全许可和合规认证需要各自授权的专业流程。本包独立完成知识整理，不要求其他 Skill。

## 输入

最低：业务问题、设备或供电对象样例、标识范围及来源。增强：端子/连接点、拓扑版本、回路/客户绑定、状态观测、有效时间/接收时间和指定标准版本。缺状态时保留 unknown；缺拓扑时交付概念草案和阻塞项。

## 工作流程

1. 固定业务范围、服务对象、event_as_of 与 knowledge_cutoff；先读 [领域记录](references/domain.json) 和 [来源目录](references/sources.json)。检索日期不是标准版本或部署适用日期。
2. 对齐设备、端子、连接点的稳定身份，将拓扑关联放入版本/有效区间；名称和同回路不证明物理相连。
3. 分开静态台账、实际状态、正常设计状态和停电事件。按 [决策方法](references/method.md) 处理未知、冲突、迟到观测及跨回路边界电源。
4. 解释供电点、客户和回路的角色与多重性。客户可有多个供电点；客户影响计数需有效绑定和去重。
5. 保留量纲、单位、相别/聚合范围和证据。DER、反送电和孤岛可能性不能用简单路径替代可行性分析。
6. 标注每项结论的标准索引、项目整理或建模推断；给出可验证问题、反例及仍缺的材料。需要图模型时可按本包方法交付数据库中立候选设计。

## 输出契约

交付范围/双时间参数；概念表（id、业务定义、身份范围、属性、来源/分类）；关系表（端点角色、方向、条件基数、版本/有效区间）；状态与不确定性表；来源版本/适用边界；假设、未决项和正反例。每项推断保留证据及原因，不把拓扑候选写成已确认客户停电。

## 资源与质量检查

[方法](references/method.md) 包含最小决策规则；[工作示例](examples/worked-example.md) 展示 unknown 与两种时间。核对每个重要概念的来源/分类、身份、时效和单位。引用 CIM/CGMES 仅提供背景，不声称本包是标准实现。外部数据库语法生成是可选后续工作，遵循 [交接边界](references/handoff.md)。
