# healthcare-domain-knowledge

## 定位与适用范围

把医疗数据问题整理为可追踪的概念、身份、状态、时间和标准映射决策。使用明确固定的 HL7® FHIR® R4 4.0.1 作为参考版本；它不是最新 FHIR 版本，R5 或开发构建需另做映射评审。基本任务可仅用本包与用户材料完成，不依赖其他 Skill 或联网。

适用于医疗数据字典、交换数据、指标血缘及图模型设计前的知识核对。不用于临床诊断、治疗选择、真实患者识别、生产系统操作或安全/法律认证。HL7 与 FHIR 为 Health Level Seven International 的注册商标；本项目不获其背书。

## 输入

最少：业务数据问题、脱敏字段/Schema 和使用目的。可选：合成样例、FHIR 版本/实施指南、来源系统范围、资源 id/versionId、患者映射证据、状态、代码系统版本、单位、时间精度和授权边界。未给出时列为未知；不要求上传真实患者数据、身份证件或密钥。

## 工作流程

1. 写明所回答的数据问题与授权目的，确定只做本体/数据设计。先找最少证据，不从字段名称猜医疗含义。
2. 从 [知识摘要](references/domain.json) 选当前问题需要的条目，并读对应 [来源目录](references/sources.json)。标明原始标准规则、项目整理、模型建议及当地政策；把用户使用的 FHIR 版本与本包 R4 基线分开。
3. 按 [判断方法](references/method.md) 逐字段建立概念表：患者、源资源、就诊、请求、活动、观测、健康问题及证据记录。为每个字段记录其真实含义、身份范围和不支持的推论。
4. 固定四组边界：源资源身份与患者假名；请求与已执行记录；临床/生理时间与报告/入库时间；原始代码/单位与经审查的映射。重复就诊、晚到和纠正版本不能被合并掉。
5. 核查状态与缺失：R4 请求撤销使用 revoked；entered-in-error 观测保留历史但不能作有效测量；无结果、unknown、未确认问题均不能当作阴性、正常或确诊。
6. 生成下述交付物，列出证据不足和映射损失。按 [工作示例](examples/worked-example.md) 用一个正常例和至少两个反例复核。若要图模型，交付明确的概念/键/关系/约束表；无需安装其他技能。

## 输出

- 任务范围与适用版本/目的，缺失输入和假设。
- 概念/字段表：本地概念 ID、业务含义、资源/业务身份范围、生命周期、时间、来源 ID、classification。
- 标准映射表：源字段或标准概念、preserved/approximated/unmapped、丢失语义、下游影响与验证办法。
- 身份匹配证据、观测使用规则、单位/术语处理、授权与撤回边界。
- 数据问题的有证据结论、未知项及正反例；不得把建模判断写成临床结论。

## 资源与质量检查

[本地方法](references/method.md)、[知识](references/domain.json)、[来源](references/sources.json) 与 [示例](examples/worked-example.md) 均随包提供。来源外链只供可选核实；不打包第三方标准正文、术语代码表或数据库语法。

检查每条重要判断是否有来源和分类；是否把资源 id、患者假名、版本、术语版本误混；是否给 unknown 赋零、把请求变执行或把单位标签当可比较证据。原始项目内容遵循 [MIT 许可证](LICENSE)，第三方来源保留自己的条款。静态格式通过不证明医学正确性、FHIR 完整符合性或真实系统行为。
