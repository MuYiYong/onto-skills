# 环境观测与本地阈值方法

1. 固定SensorThings 1.1、服务根、资源集合和原始@iot.id类型。选择资源自身URI最稳妥；本例统一使用字符串投影ID，真实数字与字符串ID不可无记录折叠。重复记录按源身份和内容区分重放/冲突，不按到达顺序覆盖。
2. 明确Thing（设备所依附对象）、Sensor、ObservedProperty、Datastream、Observation、FeatureOfInterest及设备Location的区别。Datastream的观测类型和单位定义应有对应来源；不得按展示名猜测指标或把设备位置当被测水体。
3. 保留phenomenonTime（时刻或区间）、resultTime（可空）、validTime（可选）和本地observed_at。历史问题只使用当时已知的源记录和观测流元数据；延迟生成的结果不能用到达时间替代测量时间。
4. 检查result的类型与数值有效性、resultQuality原始结构、质量来源及实际质量审核。例子的quality_decision=accepted是用户提供的本地判断，不是OGC质量枚举；缺质量、NaN、无穷值、布尔值、缺结果均不能当作正常数值。
5. 阈值政策须明确版本、发布/授权来源、适用地区与日期、指标定义、被测对象、单位、采样/平均窗口和比较符。本例使用合成上限3 mg/L、瞬时观测、严格大于及半开时间窗口，**没有法规含义**。用户未提供真实限值时交付模型和政策缺口。
6. 仅对匹配的数值测量、单位定义、被测对象、质量和时间进行比较。区间观测、validTime限制、未知单位换算或其他observationType先列待决；空resultTime可合法保留。结论分候选超限、本地阈值内、范围外和未知；单次结果不证明排放违法、污染原因或区域环境质量。

## 数据投影与损失

input.json保留了选定标准字段，但不是完整SensorThings响应；服务分页、导航扩展、历史位置、地理几何、多维流及网络交互不在示例内。标准没有要求本例的质量准入、阈值和消息冲突策略。Graph中的观测版本、政策节点和评价节点为原创设计。转存结果时带原始字节定位及散列，保留原值，不把本地规范化值覆盖源证据。
