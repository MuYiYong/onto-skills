# industry-knowledge-discovery

## 定位与解决的问题

建立有来源、可核验的知识清单；区分标准原意、通用知识、项目整理与推断。

## 适用与不适用

在用户请求上述建模工作时使用。仅加载与当前问题相关的材料；不强制调用其他 Skill。不用于具体行业标准定义的替代、GQL 语法生成或未经授权的数据库操作。

## 输入

行业、业务范围、地区/时期、用户提供的文档或数据字典及待解问题。在线检索是可选增强；离线任务使用随附方法与用户材料，未核实标准标待验证。

## 工作流程

1. 确定行业、地区、适用日期和要回答的问题；划定材料边界。
2. 从给定材料摘取术语、别名、概念、流程、关系和规则，记录材料位置；保留歧义，不用同名自动等同概念。
3. 优先定位发布机构的正式标准、版次及勘误；网络可用时核实具体条文/字段/IRI。记录URI、版本、发布方、许可和检索日期；仅有目录摘要则说明访问范围。离线用包内或用户给定材料，待核实信息保留缺口。
4. 按 [证据规则](references/method.md) 为每个知识项分类，并把原定义、解释和建模建议分栏。
5. 形成关系候选，记录参与方、方向和条件；对相互冲突的来源记录范围/日期差异与选择理由。
6. 形成知识缺口表：缺失定义、缺失材料、核实方式、对模型的影响。缺口不阻止不依赖它的建模，但不得作为已确认事实。
7. 将术语、概念、关系、规则与来源索引交付给后续建模；只加载本任务相关知识。

## 输出

来源索引；术语/别名表；概念与关系候选；流程/规则表；冲突决定；知识缺口；适用范围和可用性结论。每项含稳定ID、分类和source_ids，以及standard_basis（source_id、locator、relation、scope）或standard_gap。直接支持与背景参考分开，原创解释和政策保留原分类。

## 资源

开始工作时读 [方法与决策](references/method.md)，需要完整演示时读 [示例](examples/worked-example.md)。资源均随本 Skill 分发；外链仅用于来源核实，不是基本功能的在线依赖。

## 质量检查与约束

用业务正反例检验输出是否覆盖需求、身份和来源。明确区分已知事实、项目方法和模型推断；缺少证据的结论标待确认。用户明确要求优先于本技能建议。静态模型审查不能冒充领域专家确认、OWL 推理或数据库原生运行结果。

需要组合时把本次输出作为下一步输入；其他技能是可选增强，基本流程独立可执行。

## 示例

用户给出资产台账和工单字典：“使用人”可能是实际保管人或登记申请人。输出两个概念候选并标注各自字段位置；在业务确认前保留该缺口，不能直接生成同义词映射。
