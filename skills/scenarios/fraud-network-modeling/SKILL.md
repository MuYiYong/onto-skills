# fraud-network-modeling

## 定位与解决的问题

将具体风险问题转成可解释、有时间和证据的业务图模型。

## 适用与不适用

用于请求的风险场景建模与图语义设计，不直接运行风控审批或写生产数据。不需要预装其他本体/金融技能。

## 输入

业务问题、时间窗口、脱敏 Schema/样例、主体/事件标识、来源和规则参数。缺失机构粒度、身份或时间口径时先列未决项；可交付不依赖缺口的模型草案。

## 工作流程

1. 明确调查问题、时间窗口、允许使用的材料和输出用途；用风险假设而非先入为主的“已欺诈”标签起步。
2. 读 [领域知识](references/domain.md) 与 [来源](references/sources.json)，盘点 Party、Account、Device/Phone、Transaction、Ownership/ControlObservation 及 EvidenceRecord。
3. 按 [证据方法](references/method.md) 区分核实身份、观测关联、异常指标、分析假设与复核结论；事件、关系与证据各有独立身份。
4. 为每条关联记录方向、有效区间、observed_at、来源、匹配方式及置信度；多个证据不能用一条覆盖写边丢掉。
5. 提取异常关系/链路及候选子图，限定时间顺序、交易方向和扩展范围；共享服务、高度节点和正常家庭/企业关系要有反例。
6. 团伙候选保留核心证据、解释路径、冲突/反证、阈值与复核状态。社区/连通性只用于候选，不自动等于共同意图。
7. 检查重复记录、晚到/冲正交易、过期关联与误合并；列出模型无法判断的事实和需要补充材料。
8. 输出调查模型、候选风险子图定义和验收用例；算法/Procedure 请求走 [外部交接](references/gql-handoff.md)。

## 输出

调查范围；实体/关系/事件/证据模型；候选风险子图和链路规则；正反证、来源与置信度；状态/复核流程；质量问题和未知事项。

## 资源

流程中链接的知识、来源、决策方法和示例均在本包内。需要完整规范化交付时参考 [图规格](references/graph-model-specification.md)；联网仅用于可选来源核实。

## 质量检查与约束

用正常业务反例测试误合并和误报，核对身份、时效、来源与规则的执行位置。推断标 model-inference；示例不是监管阈值。静态建模与实际数据库运行分别报告。Core/Finance 的组合是可选增强，只传递交付物，不依赖其他包文件。

## 标准依据与缺口

先核实包内来源与知识条目的standard_basis：固定发布机构、版次、具体定位和支持范围，再形成项目解释。standard_gap保留未核实映射、本地政策和补证路径；本地键、阈值或判定公式不因引用标准就成为官方定义。任务缺少适用版本或来源时交付不依赖缺口的部分，并明确待核实项。

交付时读取条目的standard_status：standard-backed仅表示standard_basis.scope内有已核实标准依据，其他本地规则仍按standard_gap保留；nonstandard-modeling明确标为“非标准建模”，标准未取得或精确映射未核实的原因一并列出。不得把背景页、目录或来源分类当成条目符合性。
