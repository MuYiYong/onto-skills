# manufacturing-quality-traceability

## 定位、适用与边界

交付有来源路径、双时间和数量口径的批次质量追溯模型。适用于 MES/ERP/QMS 概念与数据审查、召回候选范围和库存暴露核对；不执行生产控制、质量放行或法定召回决定。本包含全部最小知识，独立安装可完成声明任务。

## 输入

最低：系统/工厂/批次身份、实际事件键与种类、投入产出批次、数量/单位、执行时间/观测时间、种子批次和目标状态。增强：订单、设备、损耗/报废、批准转换、检验方法/样本与本地规格版本。缺数值标 unknown；不可比较量纲不能直接聚合。

## 工作流程

1. 固定追溯方向、event_as_of、knowledge_cutoff、工厂范围和候选状态。读 [领域知识](references/domain.json)、[来源](references/sources.json) 和 [方法](references/method.md)。
2. 物料定义、订单、批次、事件和设备各自定键。事件键为 source_system + event_id；批次键为 source_system + site_id + lot_id。精确重放幂等；冲突重放拒绝。
3. 用 consumed_by/produced 显式表达生产、消耗、转化、拆分、合并和返工。拆分/返工产出是新身份，不能复用输入批次制造环；设备使用是独立资源关系。
4. 双时间筛选事实，再对每个事件核对守恒基础、单位转换和损耗。质量守恒仅在用户声明适用时检查；报废产出不能再记损耗，未知数量不补零。
5. 沿物料路径找上下游候选，保留每步来源。共用设备不生成血缘；交叉污染需要另行证据与规则。
6. 按目标状态选择终端批次，按完整身份去重并聚合实际产出量。中间批次与后代不能一起计暴露；缺量保留候选且总量 unknown。
7. 将检验对齐确切本地规格版本、指标/单位与适用时间，保存样本范围和方法。标准不提供本例阈值；下游 pass 不能自动清除上游召回路径。
8. 输出 [图规格](references/graph-model-specification.md) 与 [示例/验收](examples/worked-example.md)，分别报告数量、血缘和检验结论。需要数据库语法时使用 [外部交接](references/handoff.md)。

## 输出契约

范围/双时间/候选状态；实体与事件身份；Graph Model Specification、来源和映射损失；投入产出与逐事件 reconciliation；候选批次、证据路径、去重后终端暴露量及 unknown 原因；检验与本地规格版本结果；共享资源反例、未决事项及验证层级。具体 fixture 字段和覆盖约定见 [验收约定](references/fixture-contract.md)。

## 质量检查

覆盖重放/冲突、跨工厂同号、合并/拆分/返工、报废重复、单位不兼容、缺数量、晚到事件、共享设备无血缘及检验 pass 仍在候选等反例。保留候选不等于已批准召回；静态/离线计算不证明标准符合性或数据库执行。

## 标准依据与缺口

先核实包内来源与知识条目的standard_basis：固定发布机构、版次、具体定位和支持范围，再形成项目解释。standard_gap保留未核实映射、本地政策和补证路径；本地键、阈值或判定公式不因引用标准就成为官方定义。任务缺少适用版本或来源时交付不依赖缺口的部分，并明确待核实项。

交付时读取条目的standard_status：standard-backed仅表示standard_basis.scope内有已核实标准依据，其他本地规则仍按standard_gap保留；nonstandard-modeling明确标为“非标准建模”，标准未取得或精确映射未核实的原因一并列出。不得把背景页、目录或来源分类当成条目符合性。
