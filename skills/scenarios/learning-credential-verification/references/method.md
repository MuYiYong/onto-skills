# 学习凭证的证据核对方法

1. 确定Open Badges规范和文档版次、JSON-LD上下文以及VC版本。本包固定OB3.0文档1.4.5的VC2/context3.0.3路径。按W3C VC2.0 §4.9解释validFrom/validUntil；OB9.1兼容注记存在版本标签歧义，旧issuanceDate/expirationDate需另建明确转换，不混用。
2. 区分Achievement定义、AchievementSubject获颁断言、issuer、creator和实际接收者。记录凭证id+issuer.id，保留validFrom、原始载荷和接收时间。OB§10建议百分号解码并去首尾空白后比较；源原文和比较键分开保存。本例限定为已规范化的标识，未实现任意URI规范化。名称、课程相同不证明凭证/学习者相同；本例仅支持用户明确给出的subject.id。
3. 保留Criteria、Result与Evidence的原始定位、版本、授权可读范围。证据URL只代表引用；未读内容不能声称已评审。发行者与成就创建者不必相同，实际颁发权限另需机构证据。
4. 把格式/Schema、密码学proof、状态检查、subject核对分别建为外部核查证据，绑定**同一原始载荷**、发行者、subject和状态引用。JSON相同或某字段写pass不能证明验签。刷新后的内容需重新检查，禁止把旧报告套到新载荷。
5. 按任务给定时点核对有效期间、报告检查时间/已知时点、状态机制和新鲜度。撤销、未知、不支持、过期或互相冲突的报告分别呈现；不存在状态字段不等于查到active。状态机制为可扩展结构，不能凭是否存在credentialStatus决定有效性。
6. 本例只有**模拟报告**，输出candidate_for_review表示材料可进入人工复核；credential_verified固定false、competence_confirmed未知。本技能设计证据模型，不执行密码学、远程状态查询、学历认证、学分认可或录用决策。真实任务只在外部校验确已执行且报告可溯源时准确转述该报告范围。

## 本地政策与边界

模拟例子仅选单个凭证版本，要求可信issuer、明确subject、半开有效区间、一天以内且不晚于评价时点的报告。一天是演示值，不是OB要求。同身份不同载荷或不同报告冲突不按最高分/最新到达自动择一；多个合法修订需另声明OB比较和历史保留策略。原始签名不可能经属性图投影后继续证明新表示完整性，因此签名原件单独保留。
