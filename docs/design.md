# Onto Skills 设计

项目面向需要理解行业业务并设计属性图本体的 Agent。第一阶段交付 13 个可独立复制安装的 Skill；金融知识、通用建模方法和业务场景保持分层。金融 Pack 只说明组合方法。

采用源目录即分发目录：每个 Skill 自带 references、示例和许可；不需要构建、在线知识服务、其他 Skill 或原仓库即可执行其基本任务。中心 knowledge 维护有来源的知识资产，需随 Skill 分发的子集直接维护在 Skill 本地，并由开发测试检查一致性。

考虑过发布时拷贝共享依赖与运行时解析依赖。前者易产生未构建的不可安装目录，后者引入明确禁止的运行时和依赖管理。采用自包含源资产，以少量受检查的知识副本换取可直接安装。

Graph Model Specification 用轻量 JSON 与 JSON Schema 表达节点、边、属性、身份、约束、来源、未知事项和映射损失；它是交付物，不是数据库语法或新的运行时。Core 中的示例使用非行业概念，金融模型放在金融知识和 Pack。

两个入口分别为业务数据自下而上、标准本体自上而下；合并时保留标准 IRI、企业概念及冲突决定。OWL 开放世界、无唯一名称假设、Domain/Range 推断、继承和 Restriction 均需显式记录其属性图映射差异。

GQL 任务先检查当前 Agent 的外部能力，交付已验证模型后由 nebula-gql-skills 生成语法；缺失时保留模型并提供现有工具安装指引。不得复制其 SKILL.md、参考资料、脚本或语法；观测到的 release 只是兼容性证据。

开发工具仅检查格式、资源闭包、来源、模型完整性和安装布局。CI 运行离线检查。Codex 用真实 app-server 验证发现；CC-Switch 先读当前源码与手册，无法实际运行 GUI 或 macOS 的项目必须标未验证。不会修改用户已安装 Skills。
